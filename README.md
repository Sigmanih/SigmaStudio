## 🚀 What is Sigma Studio?

**Sigma Studio is a cognitive orchestration engine** — an executable environment where AI agents create, verify, document, and organize knowledge, governed by Modelfile manifests that define their behavior.

Imagine a **team of specialized AI agents** (a mathematician, an architect, a tester, a reviewer, a viz designer) working 24/7 on your research, tracking every action, testing every theorem, and building a navigable knowledge graph of everything they produce.

**This is Sigma Studio.**

### Key Differentiators

| Feature | Why It Matters |
|:--------|:---------------|
| 🧠 **Multi-Provider AI** | Ollama (local), DeepSeek, OpenAI, Anthropic, Groq, OpenRouter — you choose the brain |
| 📜 **Manifesto System** | Every agent has a "code of conduct" written as an Ollama Modelfile. Not human instructions — executable contracts |
| 🏃 **Autopilot** | Pick a model and let it improve itself: rounds of evaluation, statistical tests, and automatic specialisation |
| 🔬 **Official Benchmark Engine** | Grade models on 11 official suites (MMLU, GSM8K, HumanEval, ARC, BBH…) with a review queue and audit |
| 🔨 **SLM Forge** | Build small language models from scratch, in Italian — pre-training, distillation, GGUF export |
| 🔌 **MCP Server Hub** | 6 integrated MCP servers (Memory, Developer, Hardware, Training, Inference, Network) |
| 🤖 **Multi-Agent Orchestration** | Parallel pipelines, context sharing, dynamic swarms, and automatic delegation |
| 🏗️ **Full-Stack AI** | From academic theory to working software: theorems → tests → D3.js visualizations → whitepapers |
| 🔒 **Sandbox Security** | Every operation is confined to whitelisted paths. No agent touches system files |
| 🧩 **Modular Architecture** | Python backend + React 19 frontend + Multi-provider AI: fully composable |

> 📐 **Want the deep technical details?** The full architecture, endpoint reference, data structures, and backend internals live in **[`architettura.md`](architettura.md)**. This README is about what you can do with the platform and how to run it.

### 💡 From a Single Prompt to a Complete Knowledge Base

All the theory files, formula sheets, interactive D3.js graphs, and test scripts visible in the screenshots were generated from **a single initial prompt** entered in the **Research Lab**:

> *"Scriviamo tutti gli argomenti e i sottoargomenti trattati in un corso di Analisi 1 matematica ingegneria con dimostrazioni, formulari, esercizi in files separati e tutto il necessario a comprendere perfettamente la materia"*

From this single input, the **Sigma Architect** coordinator and the agent pipeline:
1. **Analyzed the domain** and split the roadmap into 7 sequential modules (from Sequences to Differential Equations).
2. **Generated the theory** in Markdown files enriched with LaTeX formulas and rigorous definitions.
3. **Wrote and executed Python unit tests** (`test-engineer`) with mathematical validation and automatic self-healing on errors.
4. **Designed interactive visualizations** (`viz-designer`) ready to navigate in Sigma Lab.
5. **Authored whitepapers** and formal validation reports to certify the work.

## 💬 The Power of AI Chat & Orchestration

Sigma Studio's chat is not a simple chatbot — it's a flexible cognitive control panel featuring:

- **4 Operating Modes**:
  - **Ask**: Quick explanations and theoretical questions without modifying the workspace.
  - **Plan**: Decomposition of complex goals into micro-tasks saved directly in the Roadmap.
  - **Execute**: Real-time file creation and modification on disk with Sandbox control.
  - **Complete Task**: Assisted or autonomous resolution of specific Roadmap tasks.
- **Manifest Association**: Switch agent behavior on the fly by associating configuration Manifests, with automatic restoration when navigating between different sessions.
- **Real-Time Tracking**: Every action (file creation, command execution, validation tests) leaves a structured notification for maximum operational transparency.
- **Web Search**: Integrated search (DuckDuckGo + Wikipedia) to ground agent answers in external sources.
- **Pipelines Lab**: Design and run DAG pipelines with branching conditions, self-healing loops, and SSE progress streaming.

## 🏃 Autopilot — Let the Model Improve Itself

The **Autopilot** is the newest way to train inside Sigma Studio: choose a model and let it specialise on its own.

- **Automatic cycles**: the model is evaluated, weak skills are identified, a fine-tuning round is generated, and the result is benchmarked again.
- **Per-skill profile**: 19 skills with a double bar — the standard model in blue, the gained improvement in green — so the gain is read as a thickness, not two numbers to subtract mentally.
- **Statistical verdicts**: every round reports wins, losses, and a p-value on a dedicated holdout split, so a few dozen questions can't be mistaken for a real improvement.
- **Live diary and loss curve**: watch the training loss and the evaluation progress in real time while the cycle runs.
- **Safe by design**: the training split is deliberately **different** from the benchmark suites used to judge it — no cheating on the metrics.

Access: sidebar → `🧠 Training Lab` → **🤖 Autopilota**.

## 🧠 Training Lab — Manual Toolbox

The **Training Lab** also exposes the full manual toolbox, organized in 5 tools:

| Tool | What It Does |
|:-----|:-------------|
| 🗃️ **Dataset** | 15+ curated open-source datasets, HuggingFace search (100K+), drag & drop local import |
| ⚙️ **Training** | 4 methods (LoRA/Unsloth, SFT/TRL, Full Pre-Training, Custom Script), model picker, full hyperparameter control |
| 🔨 **Forgia SLM** | Build small language models from zero — Italian datasets, pre-training and/or distillation, GGUF export, checkpoint chat |
| 🧪 **Benchmark Test** | Official model evaluation on 11 suites with grader, review queue, audit, and multi-GPU capacity probe |
| 📊 **Monitor** | Live logs, interactive loss chart, CUDA diagnostics, job controls, **Export → Ollama** |

### 🗃️ Dataset

- **⭐ Featured**: 15 curated open-source datasets for LLM training (Alpaca, Dolly, OpenHermes, UltraChat, OpenOrca, CodeAlpaca, MetaMathQA, GSM8K, MATH, TinyStories, The Pile, Italian Dolly, OPUS-100…).
- **🔍 HuggingFace Search**: 100K+ datasets with preview and metadata.
- **📂 Local Import**: drag & drop JSONL, JSON, CSV, TXT — automatic parsing.
- **🗂️ My Datasets**: manage imported datasets and select them for training.

### ⚙️ Configuration

| Method | Description | Min VRAM | When to Use |
|:-------|:------------|:---------|:------------|
| ⚡ **LoRA (Unsloth)** | Efficient LoRA 4-bit fine-tuning | 8 GB | Recommended for most cases — 2x faster, 60% less VRAM |
| 🔬 **SFT (TRL)** | Supervised Fine-Tuning with PEFT | 12 GB | Stable and versatile, supports all HuggingFace models |
| 🌐 **Full Pre-Training** | Training from scratch on raw text | 4-80 GB | For training models from zero |
| 🛠️ **Custom Script** | Customizable Python template | — | Maximum flexibility, edit script before launching |

Base models: LLaMA 3.2, Mistral, Phi-3, Gemma + local Ollama models + custom model. Hyperparameters: epochs, batch size, learning rate, max sequence length, LoRA rank/alpha, gradient accumulation.

### 🔨 Forgia SLM (SLM Forge)

Build **small language models from scratch**:
- Italian datasets from HuggingFace, pre-training and/or distillation from a teacher model.
- Tokenizer training, architecture presets (micro/mini), vocab size, sequence length.
- GGUF and other export formats, and a **checkpoint chat** to try the model while it trains.

### 🧪 Benchmark Test

The **official model evaluation engine**:
- **11 official suites** (MMLU, GSM8K, HumanEval, ARC, BBH…) with cached datasets.
- Strong grader with a **review queue** for double, illegible, or errored answers.
- **Audit** that verifies verdicts question-by-question (false positives / false negatives).
- **Capacity probe**: measures how much parallel load a model really sustains on your GPU.
- **Multi-GPU endpoints**: launch Ollama servers bound to individual GPUs and spread the evaluation across them.

### 📊 Monitor

- Hardware strip (CUDA, GPUs, VRAM, temperature, RAM, PyTorch version) + CUDA diagnostics.
- Job selector with full history and statuses (Ready/Running/Completed/Failed/Stopped).
- Interactive SVG loss chart with automatic log parsing.
- Live terminal with color-coded SIGMA/Error/Warning/Success lines.
- **Export → Ollama**: automatic Modelfile generation, customizable system prompt, integrated `ollama create` / `ollama run`.

## 📜 Manifesto System

AI agents aren't black boxes. They're defined by **Ollama Modelfiles** that specify:
- **Identity**: "You are a mathematician specialized in number theory..."
- **Rules**: "Never modify files outside `data/`..."
- **Protocol**: "Before acting, analyze the context..."
- **Parameters**: Temperature, context window, conversation template

### Available Agents

| Agent File | Base Model | Version | Role |
|:-----------|:-----------|:--------|:-----|
| `sigma_architect.md` | llama3.2 / sigma:latest | **v7.0** | Sigma Architect — admin, main orchestrator, research coordinator |
| `agente0.md` | sigma:latest | **v7.2** | Enterprise AI Architect — extended version with full execution workflow |
| `code_architect.md` | sigma:latest | **v1.0** | Full-Stack Developer — modifies React/Python code with backup & build check |
| `math1.md` | llama3.2 | **v6.0** | Math Research Assistant — generates formal theory, proofs, exercises |
| `math-collatz.md` | llama3.2 | **v1.0** | Collatz Math Specialist — number theory, mod 6 analysis, formal proofs |
| `test-engineer.md` | llama3.2 | **v1.0** | Test Engineer — writes & executes scientific Python tests |
| `viz-designer.md` | llama3.2 | **v1.0** | Visualization Designer — creates interactive D3.js charts |
| `proof-reviewer.md` | llama3.2 | **v1.0** | Critical Reviewer — validates proofs, refutes incorrect claims |

All agent manifests are located in `manifesti/` and can be loaded via the API or the **Manifesti Gallery** in the UI.

### Create a New Agent in 30 Seconds

```bash
# 1. Create a manifesto file
cat > manifesti/my_agent.md << 'EOF'
FROM llama3.2
SYSTEM """
You are an agent specialized in molecular biology...
Rules:
- Only modify files within data/biology/
- Use exclusively Ollama provider for research
- Every discovery must generate a notification in tasks.json
"""
PARAMETER temperature 0.3
PARAMETER num_ctx 32768
EOF

# 2. Load the model into Ollama
curl -X POST http://localhost:8000/api/create_model \
  -H "Content-Type: application/json" \
  -d "{\"name\": \"my_agent\", \"modelfile\": \"$(cat manifesti/my_agent.md)\"}"
```

## 🤖 Multi-Agent Orchestration

Sigma Studio supports advanced multi-agent collaboration:

- **Parallel Orchestration**: assign tasks to multiple agents simultaneously via `/api/chat/orchestrate`.
- **Context Broker**: SQLite-based shared context between agents, letting them reference each other's work.
- **Agent Registry**: metadata management, agent templates, color-coding for UI.
- **Research Sessions**: long-running autonomous research decomposition with progress tracking.
- **Pipeline Engine**: DAG-based pipeline execution with status monitoring and stop/resume.
- **Swarm**: dynamic agent swarms with plan/execute endpoints (`/api/swarm/plan`, `/api/swarm/execute`).

## 🔒 Sandbox System

All AI agent operations are strictly confined:

- **Path Whitelist**: `data/`, `manifesti/`, `sigma_studio/src/`, `scratch/`, `core/`.
- **Module Structure**: only 5 subdirectories allowed per module: `teoria/`, `test/`, `viz/`, `docs/`, `whitepapers/`.
- **Sandbox API**: create, run scripts, install packages, and destroy isolated environments (python/node/fullstack).
- **Backup Manager**: automatic backups before critical file modifications.
- **Rollback Support**: undo changes via `/api/rollback`.

## ⚙️ Quick Start

### Prerequisites

- **Python 3.10+**
- **Node.js / npm**
- **Ollama** (for local AI — [download here](https://ollama.com))

### 🚀 Option A — One-Click Start (recommended)

```bash
# 1. Clone the repository
git clone https://github.com/Sigmanih/SigmaStudio.git
cd SigmaStudio

# 2. (Optional, on Windows) Install all dependencies once
install_dependencies.bat   # creates .venv, installs Python + npm deps, builds frontend

# 3. Start Sigma Studio — creates venv, installs deps, builds frontend, starts server
sigma_studio.bat
```

`sigma_studio.bat` handles everything: virtual environment creation, Python dependencies, npm install + build, and server startup on **http://localhost:8000** — with the optimal hardware acceleration environment (CUDA, Ollama parallelism, FlashAttention).

### ⌨️ Option B — Manual Setup

```bash
# 1. Clone the repository
git clone https://github.com/Sigmanih/SigmaStudio.git
cd SigmaStudio

# 2. Install Python dependencies
pip install -r requirements.txt

# 3. Install and build the frontend
cd sigma_studio
npm install
npm run build
cd ..

# 4. Start the backend (serves the built frontend)
python sigma_server.py
```

The backend is now live at **http://localhost:8000**.

### 🧪 Quick Verification

```bash
# Verify core modules
python -c "from core.sandbox import is_path_allowed; from core.ai_providers import load_ai_config; print('✅ System OK')"

# Verify API
curl http://localhost:8000/api/tasks

# Verify Training Lab
curl http://localhost:8000/api/training/datasets/featured

# Verify Hardware Monitor
curl http://localhost:8000/api/hardware/status

# Verify MCP Hub
curl http://localhost:8000/api/mcp/servers
```

## 🧠 Multi-Provider AI

Sigma Studio supports **6 AI providers** dynamically configurable via `config.json`:

| Provider | Type | Setup |
|:---------|:-----|:-------|
| **Ollama** 🦙 | Local (free) | `http://localhost:11434` |
| **DeepSeek** 🔍 | Cloud API | `API Key` |
| **OpenAI** 🤖 | Cloud API | `API Key` |
| **Anthropic (Claude)** 🟣 | Cloud API | `API Key` |
| **Groq** ⚡ | Cloud API | `API Key` |
| **OpenRouter** 🌐 | Cloud API (multi-model) | `API Key` |

### 4 Chat Modes

> Sigma Principle: **"A notification not left is an action that never happened."**

| Mode | Backend Params | What It Does | Notifications? |
|:-----|:--------------|:-------------|:---------------|
| 💬 **Ask** | `allow_actions=false` | AI responds without modifying anything | None (chat only) |
| 📋 **Plan** | `planning_mode=true` | Analyzes a goal and creates tasks in the Roadmap | ✅ Each task gets a creation notification |
| ⚡ **Execute** | `allow_actions=true` | AI creates, modifies, or deletes files | ✅ **Automatic**: every file action generates a notification |
| ✅ **Complete Task** | `execute_task_id` + `allow_actions=true` | Executes a specific task from the Roadmap and marks it done | ✅ Notifications for every action + completion marking |
